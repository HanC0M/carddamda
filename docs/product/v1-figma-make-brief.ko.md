# 카드담다(carddamda) V1 PRD 및 Figma Make 디자인 브리프

작성일: 2026-05-06
상태: 디자인 생성용 초안

## 제품 정의

카드담다(carddamda)는 TCG 카드를 많이 구매하는 사용자를 위한 구매 세션 가속 도구다.

이 제품은 일반적인 쇼핑 검색 앱, 가격 추적기, 컬렉션 관리 도구, 소셜 서비스, 계정 기반 쇼핑 서비스가 아니다. V1의 목적은 사용자가 네이버 스토어에서 카드 하나씩 반복 검색하는 것보다 더 빠르게 여러 카드 구매 리스트를 처리하게 만드는 것이다.

제품은 조용하고 밀도 있는 구매 작업대처럼 느껴져야 한다. 빠르고, 명확하고, 실제 구매 중에도 피로하지 않아야 한다.

## V1 목표

사용자가 한 화면에서 여러 검색어와 수량을 분리해서 입력하고, 한 번에 검색을 실행한 뒤, 요청 카드별로 묶인 결과를 훑고, 외부 상품 링크로 빠르게 이동할 수 있게 한다.

첫 번째 감동 포인트는 다음이다.

> 사용자가 카드 10개짜리 리스트를 넣었더니, 각 카드명 아래로 검색 결과가 바로 정리되어 보인다.

## 대상 사용자

TCG 카드를 자주, 많이 구매하는 헤비 유저.

이 사용자는 이미 사고 싶은 카드를 알고 있다. 탐색, 추천, 소셜 증거, 매거진형 콘텐츠가 필요한 것이 아니다. 반복 검색, 탭 이동, 뒤로가기, 복사 붙여넣기 피로를 줄이고 싶어 한다.

## 핵심 사용자 흐름

1. 사용자가 단일 화면 웹앱을 연다.
2. 왼쪽 입력 패널에 구매 리스트를 입력한다.
3. 각 행에는 검색어 입력 필드와 별도의 수량 입력 필드가 있다.
4. 사용자가 검색을 실행한다.
5. 앱이 입력 행을 검증하고 요청 카드 단위로 정규화한다.
6. 앱이 요청 카드별 로딩 상태를 보여준다.
7. 검색 결과가 요청 카드별 그룹으로 표시된다.
8. 사용자가 상품명, 가격, 판매처, 썸네일, 관련도를 훑는다.
9. 사용자가 외부 상품 링크를 연다.
10. 사용자가 카드담다로 돌아와 다음 카드를 계속 처리한다.

## V1 기능 요구사항

### 구매 리스트 입력

- 검색어와 수량을 분리한 반복 입력 행을 제공한다.
- 각 행에는 검색어 입력 필드와 별도의 수량 입력 필드가 있어야 한다.
- 여러 행을 빠르게 추가, 삭제, 수정할 수 있어야 한다.
- 가능하면 붙여넣기 친화적인 보조 입력은 허용할 수 있지만, V1의 기본 입력 모델은 자유 텍스트 textarea가 아니라 구조화된 행이다.
- 검색 전 또는 검색 중에 검증된 요청 카드 목록을 보여준다.
- 사용자가 입력한 검색어는 검증 중에도 유지한다.
- 검증 경고는 전체 세션을 막지 않고 명확히 보여준다.

입력 예시:

```text
검색어: 피카츄 ex      수량: 2
검색어: 리자몽 VMAX   수량: 1
검색어: 나오하        수량: 3
```

### 세션 검증

- 검색어와 수량을 별도 필드로 다룬다.
- 새 행의 기본 수량은 1로 둔다.
- 검색 실행 전 검색어가 비어 있지 않아야 한다.
- 잘못된 행은 경고로 보여준다.
- 잘못된 행을 조용히 숨기거나 버리지 않는다.

### 검색 실행

- 유효한 모든 요청 카드에 대해 검색을 실행한다.
- 전체 세션 진행 상태를 보여준다.
- 요청 카드 그룹별 로딩 상태를 보여준다.
- 실패한 그룹만 다시 시도할 수 있어야 한다.
- 한 그룹 실패 때문에 전체 세션을 처음부터 다시 시작하게 만들지 않는다.

### 그룹화된 결과

- 결과는 반드시 요청 카드별로 그룹화되어야 한다.
- 각 결과가 어떤 요청 카드에 속하는지 항상 명확해야 한다.
- 각 그룹에는 다음 정보가 있어야 한다.
  - 요청 카드명
  - 요청 수량
  - 결과 개수
  - 그룹 상태
  - 결과 목록

### 상품 결과 항목

각 결과 항목에는 다음 정보가 포함되어야 한다.

- 상품 썸네일
- 상품명
- 가격
- 판매처 또는 스토어명
- 가능한 경우 간단한 메타데이터
- 외부 링크 이동 액션

외부 링크 이동이 상품 단위의 주요 액션이다. V1은 자동 장바구니 담기를 제공하지 않는다.

### 필수 상태

디자인에는 다음 상태가 일급 UI로 포함되어야 한다.

- 검색 전 idle 상태
- 검증 경고
- 전체 로딩 상태
- 그룹별 로딩 상태
- 정상 결과 상태
- 특정 요청 카드의 결과 없음 상태
- 일부 그룹 실패 상태
- 실패한 그룹 재시도 상태

## 디자인 톤

`docs/design/carddamda-design-system.md`의 Spotify-inspired dark app system을 기준으로 한다.

차분하고 명확하되, 밝은 대시보드가 아니라 어두운 구매 세션 작업 공간으로 디자인한다.

인터페이스는 다음처럼 느껴져야 한다.

- 빠름
- 컴팩트함
- 신뢰감 있음
- 실용적임
- 구매자 중심
- 정보 밀도는 높지만 답답하지 않음
- 어두운 앱 표면 위에서 상품 이미지와 상태가 돋보임

인터페이스는 다음처럼 느껴지면 안 된다.

- 일반 이커머스 홈 화면
- 카드 컬렉션 갤러리
- 소셜 앱
- 마케팅 랜딩페이지
- 장식적이거나 과하게 발랄한 화면
- 카드형 UI가 과하게 많은 화면
- 밝은 일반 업무용 대시보드

시각적 참고 방향:

- Spotify식 어두운 앱 몰입감과 집중된 구매/조달/트레이딩 작업 공간을 결합한다.
- 라이프스타일 쇼핑 앱처럼 보이면 안 된다.

## 레이아웃 방향

V1은 단일 화면 웹앱이다.

권장 데스크톱 레이아웃:

- 왼쪽 고정 너비 패널: 구조화된 세션 입력 및 검증된 목록
- 오른쪽 유동 영역: 요청 카드별 결과 그룹
- 상단의 컴팩트한 명령 행: 검색, 새로고침, 세션 요약
- 랜딩 히어로 없음
- 온보딩 카드 없음
- 홍보 섹션 없음

권장 모바일 레이아웃:

- 입력과 결과를 세로로 쌓는다.
- 검증된 목록 요약을 쉽게 다시 확인할 수 있어야 한다.
- 결과 그룹은 모바일에서도 명확히 분리되어야 한다.
- 외부 링크 액션은 엄지로 누르기 쉬워야 한다.

## 정보 구조

주요 위계:

1. 세션 입력
2. 검증된 요청 카드
3. 검색 상태
4. 요청 카드별 결과 그룹

요청 카드 그룹이 UI의 중심 단위다. 상품 결과는 절대 그룹 없는 피드처럼 보이면 안 된다.

## 타이포그래피 규칙

한글, 영문, 숫자가 함께 나와도 깨끗하게 읽히는 산세리프를 사용한다.

권장 폰트 스택:

```css
font-family: Pretendard, Inter, "Apple SD Gothic Neo", "Noto Sans KR", system-ui, sans-serif;
```

타입 스케일:

- 앱 제목: 18-20px, 700
- 패널 제목: 14-16px, 650
- 요청 카드 그룹 제목: 15-16px, 700
- 상품명: 13-14px, 500-600
- 가격: 14-15px, 700
- 판매처 및 메타데이터: 12-13px, 400-500
- 상태 라벨: 11-12px, 600
- 버튼: 13-14px, 600

규칙:

- 히어로급 대형 타이포그래피를 쓰지 않는다.
- 개성보다 빠른 스캔을 우선한다.
- line-height는 컴팩트하되 읽기 불편하지 않아야 한다.
- 상품명은 최대 두 줄까지 허용한다.
- 가격은 세로 비교가 쉬워야 한다.
- 수량은 요청 카드명 가까이에 붙여 보여준다. 메타데이터 안에 묻히면 안 된다.

## 컬러 시스템

어두운 중립색 기반에 명확한 주요 액션 컬러 하나를 사용한다.

권장 토큰:

```text
Background: #121212
Surface: #181818
Surface raised: #1f1f1f
Surface card: #252525
Text primary: #ffffff
Text secondary: #b3b3b3
Text tertiary: #cbcbcb
Primary action: #1ed760
Primary action hover: #1db954
Border muted: #4d4d4d
Border strong: #7c7c7c
Error: #f3727f
Warning: #ffa42b
Info: #539df5
```

규칙:

- near-black 계열 표면을 기본 앱 환경으로 사용한다.
- 초록색은 주요 검색, 활성 상태, 핵심 CTA에만 사용한다.
- 초록색을 장식용 배경으로 쓰지 않는다.
- 상품 이미지, 판매처 배지, 상태 표시가 주요 비초록 색상 소스가 되게 한다.
- 그라디언트를 주요 시각 정체성으로 쓰지 않는다.

## 간격, 밀도, 형태

컴팩트한 작업용 간격을 사용한다.

- 데스크톱 페이지 패딩: 20-24px
- 패널 간격: 16px
- 그룹 간격: 12-16px
- 결과 항목 패딩: 10-12px
- 입력창 패딩: 12px
- 버튼 높이: 34-38px
- 작은 컨트롤 높이: 28-32px
- 결과 그룹 radius: 6-8px
- 버튼 radius: 500px-9999px pill
- 아이콘 버튼 radius: 50% circle

규칙:

- 카드는 장식용이 아니라 기능적 컨테이너여야 한다.
- 카드 안에 카드를 중첩하지 않는다.
- 주요 버튼과 컨트롤은 pill/circle 지오메트리를 따른다.
- 반복되는 결과 항목은 빠른 비교를 위해 정렬을 맞춘다.
- 가능하면 안정적인 행 높이를 사용한다.

## 인터랙션 규칙

- 검색은 가장 명확한 주요 액션이어야 한다.
- 외부 링크는 상품 단위에서 가장 명확한 액션이어야 한다.
- 일부 실패는 성공한 그룹 탐색을 막으면 안 된다.
- 결과 없음은 해당 요청 카드 아래에서 보여야 한다.
- 한 그룹이 실패해도 사용자는 다른 그룹을 계속 훑을 수 있어야 한다.
- 일반적인 흐름에는 모달을 사용하지 않는다.

## Figma Make 프롬프트

아래 프롬프트를 Figma Make에 사용한다.

```text
카드담다(carddamda)라는 단일 화면 웹앱을 디자인해줘.

카드담다(carddamda)는 TCG 카드를 많이 구매하는 사용자를 위한 구매 세션 가속 도구야. 일반 쇼핑 검색 앱이나 이커머스 랜딩페이지가 아니야. 핵심 목적은 사용자가 네이버 스토어에서 카드 하나씩 반복 검색하는 것보다 더 빠르게 여러 카드 구매 리스트를 처리하게 만드는 거야.

차분하고, 컴팩트하고, 명확한 구매 작업 공간으로 디자인해줘. 속도, 스캔, 요청 카드별 그룹화된 검색 결과가 가장 중요해.

화면에는 반드시 다음이 포함되어야 해:
- 왼쪽 세션 입력 패널. 각 행마다 검색어 입력 필드와 별도의 수량 입력 필드가 있어야 함.
- 구매 요청 행을 빠르게 추가, 삭제, 수정할 수 있는 컨트롤.
- 검증된 요청 카드 목록 미리보기. 각 카드명과 수량이 보여야 함.
- 빈 검색어, 잘못된 수량, 중복처럼 보이는 행에 대한 검증 경고 예시.
- 주요 Search 버튼, 세션 상태, 새로고침/재시도 affordance가 있는 컴팩트한 명령 행.
- 오른쪽 메인 결과 작업 공간.
- 검색 결과는 일반 피드가 아니라 요청 카드별로 그룹화되어야 함.
- 각 결과 그룹은 요청 카드명, 요청 수량, 결과 개수, 상태를 명확히 보여줘야 함.
- 각 상품 결과 행은 썸네일, 상품명, 가격, 판매처/스토어명, 간단한 메타데이터, 외부 링크 버튼을 보여줘야 함.
- 검색 전 idle, loading, no results, partial failure, 특정 그룹 retrying 상태가 first-class UI로 보여야 함.

시각 스타일은 Spotify에서 영감을 받은 어두운 앱형 작업 도구로 만들어줘:
- near-black 배경(#121212), dark surface(#181818, #1f1f1f), white text, silver secondary text를 사용.
- 주요 액션 컬러는 초록색(#1ed760) 하나만 사용. 검색, 활성 상태, 핵심 CTA에만 적용.
- 버튼과 주요 컨트롤은 pill 형태(500px-9999px radius), 아이콘 버튼은 circle 형태.
- 상품 이미지와 판매처 배지가 비초록 색상의 주요 출처가 되게 함.
- heavy shadow와 dark surface variation으로 깊이를 만들고, 밝은 대시보드처럼 보이지 않게 함.
- warning, error, info 상태 컬러는 명확하게 사용.
- 그라디언트, 장식용 blob, 마케팅 hero, 소셜 기능, 계정 UI는 넣지 말 것.
- 과하게 큰 카드나 갤러리형 탐색 화면을 피할 것. 이건 실제 구매 세션을 처리하는 작업 인터페이스야.

한글, 영문, 숫자가 잘 섞이는 타이포그래피를 사용해줘:
- Pretendard 또는 유사한 한글 친화 산세리프.
- 앱 제목은 18-20px bold 정도.
- 그룹 제목은 15-16px bold 정도.
- 상품명은 13-14px medium 정도.
- 가격은 14-15px bold 정도.
- 메타데이터는 12-13px 정도.
- 빠른 스캔을 위해 line-height는 컴팩트하게.
- 영어만 있는 버튼 라벨은 uppercase와 넓은 letter spacing을 사용할 수 있지만, 한국어 라벨에는 억지로 적용하지 말 것.

시각적 위계에서 요청 카드 그룹이 중심 단위가 되어야 해. 사용자는 각 상품 결과가 어떤 요청 카드에 속하는지 항상 알 수 있어야 해.

데스크톱 레이아웃:
- 왼쪽 고정 너비 입력 패널.
- 오른쪽 유동형 그룹 결과 작업 공간.
- 상단의 컴팩트한 명령/상태 행.
- 단일 화면 앱이며 랜딩 섹션은 없음.

모바일 레이아웃:
- 입력과 결과를 세로로 쌓기.
- 그룹 정체성과 외부 링크 액션이 모바일에서도 명확하고 누르기 쉬워야 함.

목업에는 다음과 같은 한국어 TCG 카드 예시 데이터를 넣어줘:
- 피카츄 ex x2
- 리자몽 VMAX x1
- 나오하 x3
- 루기아 VSTAR x1

현실적인 혼합 상태를 보여줘:
- 여러 결과가 있는 그룹 하나.
- 로딩 중인 그룹 하나.
- 결과가 없는 그룹 하나.
- 복구 가능한 오류와 retry 액션이 있는 그룹 하나.
```

## 디자인 승인 기준

생성된 디자인은 다음을 만족해야 한다.

- 랜딩페이지가 아니라 단일 화면 앱이어야 한다.
- 데스크톱에서 왼쪽 입력 패널과 오른쪽 그룹 결과 영역이 모두 보여야 한다.
- 상품 결과가 요청 카드별로 그룹화되어야 한다.
- 수량이 각 요청 카드 가까이에 보여야 한다.
- 로딩, 빈 결과, 일부 실패 상태가 보여야 한다.
- 외부 상품 링크 액션이 명확해야 한다.
- `docs/design/carddamda-design-system.md`의 어두운 앱 팔레트와 pill/circle 컨트롤 규칙을 따라야 한다.
- 계정, 소셜, 알림, 결제, 자동 장바구니 기능이 없어야 한다.
- 사용자가 카드 10개짜리 구매 리스트를 네이버 스토어에서 직접 처리하는 것보다 빠르게 처리할 수 있어 보여야 한다.

## 향후 구현 메모

이 문서는 제품 및 디자인 목표를 정의한다. 구현 시에는 세션 입력 검증, 공급자 로직, 결과 정규화, 링크 생성을 독립적으로 테스트 가능하게 유지해야 한다. UI 컴포넌트가 공급자 HTML을 직접 파싱하면 안 된다.

완료된 디자인 프로토타입은 `designbase/`에 있다. 프론트엔드 구현 시 구체적인 레이아웃, 컴포넌트 구조, 상태 표현, spacing, visual treatment는 `designbase/ShoppingCarta.html`과 `designbase/app.jsx`를 우선 참고한다.

상품 수집 및 공급자 통합 규칙은 `docs/architecture/search-provider-contract.md`를 기준 사양으로 사용한다.
